# 병원 홈페이지 제작과 화면 검수

기획서와 참고자료를 받아 프로젝트의 전체 범위를 한 번에 접수한다. 설계와 제작, 검수는 페이지별로 끝낸다. 리셋에서 이미 완성한 디자인을 참고하라는 요청은 실제 컴포넌트, 스타일, 모션을 확인하고 가져오라는 뜻이다. 여러 페이지를 맡았다는 이유로 각 페이지의 사진, 비교 도식, 전환 구간, 모션을 생략하지 않는다.

## 제작 키트 열기

- 스킬의 `assets/reset-clinic-kit.zip`을 현재 프로젝트의 작업용 폴더 아래 **새 경로**에 푼다. 압축은 검증된 실제 소스·이미지와 기준 화면을 함께 담고 있다. 로컬 Windows에서는 `Expand-Archive -LiteralPath <ZIP> -DestinationPath <새 작업 폴더>`를 쓸 수 있다. 병원의 기존 파일 위에 압축을 풀지 않는다.
- 압축을 푼 폴더의 [제작 키트](assets/reset-clinic-kit.zip)에서 `kits/clinic-site/README.md`, `references/catalog.json`, `references/index.html`, `new-site.plan.example.json`을 확인한다. 목록의 링크 또는 포함된 `app/`에서 실제 코드와 스타일을 찾는다. 비교 대상은 메인, 재생치료 소개, 리젠 주사, PRP·PRF, 스포츠손상 센터, 원장소개 여섯 페이지다.
- 저장소에 포함된 스킬 원본을 직접 읽는 경우 상위 `kits/clinic-site`와 리셋 저장소의 기준 커밋 `65767b3`을 사용할 수 있다. 설치된 스킬은 위 ZIP을 사용하므로 새 병원 작업 폴더에서 리셋 저장소에 접근할 필요가 없다.

## 전체 요청을 페이지 단위 작업으로 진행

1. **입력 정리.** 자료와 현재 프로젝트를 읽고 사이트맵, 대상 URL과 우선순위, 환자가 알아야 할 내용, 브랜드·사진 기준을 파악한다. 새 병원이라면 그 병원의 이름, 연락처, 진료 범위, 의료진과 사진을 사용한다. 확인되지 않은 경력·비용·치료 효과나 의료진 검토 사실을 만들어 넣지 않는다. 사용자가 준 기준이 더 구체적이면 그 기준을 우선한다.
2. **페이지별 계획.** 기획 JSON에 대상 URL을 모두 넣는다. 페이지마다 목적과 환자 질문의 순서를 정하고, 각 섹션에 카탈로그의 `페이지/섹션` ID, 사용할 구현 파일, 사진의 역할, 유지할 글자 크기·정렬·모션과 확인할 동작을 기록한다. 특히 첫 화면뿐 아니라 중반 전환부와 하단의 배치도 원본과 연결한다. 단순 목차만으로 구현을 시작하지 않는다.
3. **원본 코드 연결과 구현.** 지정한 실제 JSX 구조, 관련 CSS의 적용 순서, 스크롤 모션 또는 상호작용 컴포넌트를 검토하고 프로젝트에 맞게 재사용한다. 역할이 같은 히어로는 원본 제목 규격과 높이를 유지하고, 페이지 중간은 사진·본문, 카드, 비교, 단계, 패럴랙스 등 내용을 설명하는 데 필요한 형식을 사용한다. 새 치료센터는 스포츠손상 센터처럼 환자 대상과 진료 흐름이 먼저 이해되게 하고, 원장소개는 인물 컷아웃·진료 철학·경력·저서나 방송 중 실제 자료가 있는 부분을 활용한다. 원본의 구조를 바꿀 필요가 있으면 환자에게 더 명확한 대체 방식과 이유를 계획에 남긴다. 각 페이지를 끝까지 구현하고 다음으로 진행한다. 사용자가 기획만 요청했다면 기획까지 제공한다.
4. **브라우저 검사.** 대상 사이트를 빌드하여 띄우고 완성 URL 전체에 키트의 `kit.mjs audit <origin> <plan.json> <결과 폴더>`를 실행한다. 기본 PC 1440×900, 모바일 360×800에서 필수 섹션과 순서, 뒤쪽 이미지·표·패럴랙스 구조, 선택한 제목·높이 기준, 가로 넘침과 설계한 클릭·스크롤 동작을 확인한다. 화면에 영향을 주는 공통 CSS와 모션·콘텐츠 파일은 계획의 `watch`에 넣는다. 실패한 페이지를 고쳐 다시 검사한다.
5. **기준 화면 비교 후 완료.** 페이지마다 PC와 모바일을 기준 JPG와 같은 너비로 비교한다. 상단·중단·하단에서 사진과 글의 시작·끝, 핵심 피사체 크롭, 제목 줄바꿈, 설명과 사진이 교차하는 흐름을 본다. 일반 모션 상태에서 스크롤과 메뉴·링크·모달을 직접 확인한다. 그 화면에서 실제로 본 차이와 수정 사항을 `review.json`에 기록하고 `kit.mjs ready <report.json> <plan.json>`을 통과시킨다. 미확인 항목을 통과로 표시하지 않는다. 환경상 확인할 수 없는 항목은 결과에 무엇이 미검증인지 알린다.

사용자는 전체 제작을 한 번에 맡길 수 있다. 일상적인 디자인 선택이나 페이지별 검수 승인을 사용자에게 떠넘기지 않는다. 최종 보고에 제작 URL, PC·모바일 확인 범위와 확인이 필요한 병원 사실을 구분해서 담는다. GitHub 푸시와 공개 배포는 그 프로젝트에서 이미 부여된 권한과 배포 환경에 따른다.
