# 리셋 병원 홈페이지 제작 키트

여섯 기준 페이지의 실제 소스, 섹션별 찾아보기, PC·모바일 기준 이미지, 일괄 제작용 계획서와 검수 스크립트입니다. 기준 코드 버전은 `65767b3`입니다. [기준 화면 열기](references/index.html)에서 각 페이지를 확인하세요. JPG는 전체 길이입니다. [섹션과 코드 위치](references/catalog.json), [실측 수치](references/metrics.json), [리셋 여섯 페이지 검수 예제](reset-reference.plan.json)가 함께 들어 있습니다.

## 다음 병원 제작에 사용하는 순서

| 단계 | 에이전트가 하는 일 | 다음 단계로 넘어가는 기준 |
| --- | --- | --- |
| 1. 일괄 접수 | 전체 사이트맵, 기획서, 병원 브랜드·사진·확인된 진료 정보를 한 번에 읽고 페이지별 목표를 만든다. | 전체 URL과 대상 페이지 수가 확정돼 있다. |
| 2. 페이지별 설계 | 페이지마다 환자 질문을 순서대로 놓고 섹션마다 기준 페이지/섹션, 실제 조립할 코드, 유지할 요소를 기록한다. | 히어로뿐 아니라 중간과 끝의 전환, 사진, 비교·과정·FAQ 등 해당 주제에 필요한 섹션도 지도에 들어 있다. |
| 3. 페이지별 제작 | 지정한 JSX 구조와 CSS, 필요한 관찰/모달 컴포넌트와 이미지 구현을 가져온다. 병원별 문구, 사진, 링크를 연결한다. | 한 페이지 단위로 상단·중단·끝까지 구현한다. 여러 페이지 작업량 때문에 남은 페이지의 카드나 사진을 임의로 걷어내지 않는다. |
| 4. 일괄 브라우저 검사 | PC 1440×900, 모바일 360×800에서 모든 페이지의 전체 화면과 실측을 저장한다. 페이지별 버튼, 해시, 모달, 실제 스크롤 동작을 확인한다. | 한 페이지가 실패해도 나머지를 검사하고, 실패한 페이지를 다시 고친다. |
| 5. 기준 대비 화면 검수 | 기준 JPG와 새 페이지 JPG를 같은 너비로 열고 상단→중간→하단을 직접 본다. PC·모바일별로 짧은 관찰과 확인 항목을 기록한다. | 제목·정렬·크롭·화면 흐름·모션·이동 기능을 실제 확인한다. 실패하거나 기록이 빠진 페이지가 있으면 완료 처리하지 않는다. |

새 병원에서는 로고·색·주소·의료진·촬영 자료를 바꿉니다. 리셋의 의료 문구, 병원 정보, 경력, 전화번호, 링크, 사진은 출처로 다루고 새 병원으로 자동 복사하지 않습니다. 치료 효과·비용·약력·시술 가능 여부는 병원이 제공하거나 확인한 사실을 사용합니다. 승인되지 않은 게시·배포는 제작 명령의 자동 단계로 넣지 않습니다.

## 어떤 코드를 가져올지 고르는 법

| 원본 | 대표 섹션 | 소스와 조립 포인트 |
| --- | --- | --- |
| 메인 | 히어로, 재생치료/센터 카드, 네 가지 관점, 치료 과정, 칼럼 | `app/components/HomePage.js`, `RegenHero.js`, `ResetPrinciples.js`, `HomeScrollMotion.js`. 배경을 고르는 picture, 첫 이미지 우선 로드, 슬라이드별 문구와 점 버튼 구조. 카드 사진 비율과 모바일 크기를 함께 가져온다. |
| 재생치료 소개 | 정의, WHY 카드, 사진·본문, 환자 중심 원형 도식, FAQ | `app/components/RegenOverview.js`, `RegenOverviewMotion.js`, `app/regen-overview.css`. 전체 배경 히어로, 중앙 제목, 카테고리 바 다음의 정의, 밝음·어두움 전환을 기준으로 삼는다. |
| 리젠 주사 | 선택지 카드, 평가 사진·본문, 치료 과정, FAQ | `app/components/RegenInjection.js`, `app/regen-overview.css`, `app/regen-editorial.css`. 카드와 긴 설명을 나누고, 사진과 평가 목록을 한 묶음으로 가져온다. |
| PRP·PRF | 성분 패럴랙스, PRP·PRF 비교, 근거, 복수 단계의 설명 | `app/components/RegenPrpPrf.js`, `app/regen-prp-prf.css`, `app/regen-overview.css`. 실제 `Band` 구조의 사진·큰 제목·본문과 인용 링크를 함께 본다. |
| 스포츠손상 센터 | 프로그램, 치료 선택 과정, 복귀 평가, 원장 컷아웃 | `app/components/SportsCenter.js`, `app/sports-clinic.css`, `app/center-care-program.css`. 짧은 대상 요약, 프로그램 강조, 선택 과정 바로가기와 단계 흐름을 가져온다. |
| 원장소개 | 배경에 녹는 인물, 경력 패럴랙스, 저서, 방송 모달·TV | `app/about/doctor/page.js`, `profile.css`, `BroadcastStrip.js`와 `app/about-detail.css`. 인물 사진의 경계와 모바일 크롭, 모달에서 다른 방송 한 장씩 넘기는 동작을 검수한다. |

컴포넌트만 잘라내기 전에 해당 라우트 import와 `app/layout.js`의 전역 CSS 순서를 확인합니다. 공통 타이포·여백은 원본 역할에 맞춰 연결하고 색만 브랜드 변수로 조정합니다. 사진과 글이 나오는 구간을 단일 텍스트 블록으로 대체할 필요가 있다면, 먼저 계획에 환자에게 더 잘 설명되는 대체 방식을 적습니다. 근거나 장면으로 전달할 정보가 없는 곳에 숫자나 모션을 채워 넣을 필요도 없습니다.

## 실행

Node.js 22 이상과 Chrome이 필요합니다. Playwright가 이미 설치되어 있으면 그대로 사용합니다. 별도 설치 시 프로젝트 루트에서 `npm install --prefix kits/clinic-site --no-save --package-lock=false playwright`를 실행합니다. 외부 환경에 이미 설치된 Playwright를 사용할 때는 `PLAYWRIGHT_MODULE`에 모듈 파일의 경로나 file URL을 지정합니다.

1. 새 병원 저장소 안에 `kits/clinic-site` 폴더를 복사합니다. [새 사이트 계획 예제](new-site.plan.example.json)를 작업 위치에 복사해 사이트맵과 코드 위치를 채웁니다. 소스 경로는 계획서 파일 기준 상대 경로입니다. 예제에서 가정한 새 병원의 파일은 직접 생성합니다.
2. 에이전트에게 계획과 [일괄 제작 지시문](PRODUCTION-PROMPT.md)을 전달합니다. 모든 페이지를 대상으로 한 번에 요청할 수 있습니다.
3. 대상 사이트의 프로덕션 빌드를 띄운 뒤 실행합니다. 결과는 대상 사이트 작업 폴더 아래에 저장됩니다.

```powershell
node kits/clinic-site/kit.mjs audit http://127.0.0.1:3100 path/to/site.plan.json .build-tmp/clinic-kit
```

4. `report.json`의 실패를 고치고 다시 실행합니다. 이어서 각 페이지의 PC·모바일 JPG를 기준 JPG와 비교합니다. `review.json`에는 각 화면의 확인 항목과 실제로 관찰한 내용을 기록합니다. 스크린샷만으로 애니메이션을 볼 수 없으므로 해당 페이지는 브라우저에서 일반 모션으로 열어 스크롤하면서 확인합니다.
5. 검수 기록을 검사합니다. 기록이 빠졌거나, 검사 후 계획·등록된 소스·스크린샷이 바뀌면 실패합니다.

```powershell
node kits/clinic-site/kit.mjs ready .build-tmp/clinic-kit/report.json path/to/site.plan.json
```

### 계획서 필드

- `goal`, `purpose`에는 페이지의 목적과 섹션이 답할 질문을 적습니다. `reference`는 카탈로그의 `페이지 ID/섹션 ID`입니다. `implementation`은 그 섹션을 렌더링하는 실제 파일입니다.
- `keep`은 원본의 유지 조건입니다. `lockTypography`는 제목 크기와 굵기를, `lockHeight`는 기준 높이 ±24px를 확인합니다. 역할이 같은 구간에서만 선택합니다.
- 기준 섹션에 사진, 표, 패럴랙스 배경 레이어가 있으면 해당 구조가 있는지 기본 검사합니다. `minimum`으로 카드 수, 이미지, 특정 모션 훅 등의 조건을 강화할 수 있습니다. 대체 구성이 필요한 경우 `allowPatternChange`에 이유를 적고 필요한 대체 요소를 `minimum`에 지정합니다.
- `interactions`에는 클릭할 요소 또는 스크롤할 요소와 확인할 결과를 지정합니다. URL/해시 이동, 모달 열림, 캐러셀 활성 슬라이드, 스크롤에 따른 상태 변화를 확인할 수 있습니다.
- `watch`에는 섹션 구현 파일 외에 CSS·레이아웃·모션·콘텐츠 데이터처럼 화면에 영향을 주는 파일을 추가합니다.

자동 검사의 범위는 URL 응답, H1, 섹션 존재와 순서, 지정한 구조·수치, 가로 넘침, 주요 동작입니다. 사진의 시선 방향, 여백의 균형, 페이지 전체의 디자인 흐름은 기준 화면과 직접 비교해 기록합니다. 검수 스크립트가 그 미적 판단을 대신하지 않습니다.

## 리셋 원본을 다시 실행

키트의 저장소 버전에는 소스가 이미 있습니다. 배포용 ZIP에도 동일 커밋의 `app`, `lib`, `public`, Next 설정과 의존성이 들어 있습니다. ZIP에는 환경 비밀값과 배포 설정을 넣지 않습니다. 풀고 프로젝트 루트에서 `npm ci`, `npm run build`, `npm run start`를 실행하면 원본을 로컬에서 확인할 수 있습니다.

예제는 리셋 여섯 페이지 자체를 다시 검수하는 용도입니다.

```powershell
node kits/clinic-site/kit.mjs audit http://127.0.0.1:3100 kits/clinic-site/reset-reference.plan.json .build-tmp/reset-qa
```

기준을 바꿀 때만 `capture <origin>`을 사용합니다. 이 명령은 기준 JPG와 실측 파일을 새로 저장하므로 대상 사이트 검수와 혼동하지 않습니다.
